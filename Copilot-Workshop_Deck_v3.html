    what changed since last year

    Copilot stopped suggesting.
    It started doing.

    Agent mode runs a loop: it reads, acts, checks the result, and goes again until the job is done.

    Click 3 times. Read files, act (edit, run commands), check (tests, browser). Then repeat. Our job today: shape that loop with rules, tools and recipes.

    Teach it how your team works

    Custom instructions: plain markdown files that tell Copilot how your project works.

    custom instructions

    Context you write once, Copilot reads every time

    Three clicks. 1: what you type. 2: the files that get added for you. copilot-instructions.md is always added. *.instructions.md files only when the agent touches matching files (applyTo glob). AGENTS.md is a shared format other agents read too. 3: everything is merged into one context. Rule of thumb: write instructions like onboarding notes for a new colleague. Short, concrete, testable.

    .github/copilot-instructions.md

    House rules,
    always on

    No need to repeat yourself in every prompt. The repo carries the context.

    # TicketLab Lite: how to work here - Plain Node.js 22. No new npm packages. - Data goes through store.js only. - Run npm test before and after. - Never weaken a test to pass. - Keep changes small. - Finish with 3 bullets.
    Highlight each rule. Say: watch Copilot follow these without me repeating them.

    the problem mcp solves

    Every AI app × every tool = a mess

    Before MCP: every AI app builds its own connector to every tool. N times M. With MCP: apps speak one protocol, each tool ships one server. N plus M. Same idea as USB-C or the Language Server Protocol. Build your ServiceNow MCP once, every agent can use it.

    model context protocol

    One plug, many tools

    Click 1: inside the host, one client per server connection. A client is a connector, not another AI. Click 2: two servers, one standard. Click 3: each server exposes tools. Think USB-C for AI.

    one tool call, step by step

    You stay in the loop

    Four clicks. The important one is the yellow box: VS Code asks you before a tool runs. MCP does not make tools safe by itself; permissions and review do.

    playwright mcp · the eyes

    A real browser the agent can drive

    tool calls
    browser_navigate  localhost:3000
browser_select_option  High
browser_snapshot
browser_take_screenshot

    It reads the accessibility tree: text and roles, not pixels. Fast, cheap and precise.

    Playwright MCP is Microsoft's MCP server around Playwright. The agent opens a real browser and gets tools like navigate, click, type, select, snapshot, screenshot. Key point: the snapshot is the accessibility tree, structured text. The agent compares 2 list items with "6 tickets" and finds the bug our tests could not see.
    server.tool( "create_ticket", "Create a new open ticket.", { title: z.string(), priority: … }, async (args) => addTicket(args) );

    act three · parallel agents

    One agent is good.
    Two is a team.

    Two independent tasks: fix the counter, and build a new close_ticket tool. First, the trick that makes it safe: git worktrees.

    before the demo · what is a git worktree?

    One repository, several folders, each on its own branch

    git checkout

    One folder. Switching branch replaces the files under your feet. Two agents here = they overwrite each other.

    git worktree

    Extra folders that share the same history. Each one has its own branch, files and running app.

    Click 1: the problem. With a normal checkout, two agents in one folder step on each other. Click 2: worktree. The command is git worktree add ../folder -b branch. All folders share one .git, so commits from one are visible from the others and merging is normal git. Cheap to create, cheap to delete.

    !

    Watch out

    New worktree = committed files only. Run npm install, copy .env, use another port.

    Six clicks. The last card matters for the demo: a new worktree has no node_modules and no .env. Our instructions file tells the agent to run npm install if node_modules is missing.

    git worktree

    Two folders, one repo, no collisions

    The Agents window creates these worktrees for you (fallback: npm run parallel). Separate folders, separate branches, separate ports. They touch different files: app.js vs ticket-server.js. You are the reviewer now, not the typist.

    subagents

    An agent that delegates to specialists

    Each subagent works in a fresh, isolated context and returns only the result.

    Your main chat stays small. Specialists can use a different model and fewer tools.

    .github/agents/*.agent.md

    Subagents run inside one session, not in parallel worktrees. Worktrees isolate files; subagents isolate context. A custom agent is a markdown file with a name, description and tool list. Our two are read-only: tools read and search. Make sure Run Subagent is enabled in Configure Tools.

    act four · recipes

    Package the routine
    as a skill

    A folder with a SKILL.md. Loaded only when your request needs it.

    what is a skill?

    A folder that teaches the agent a routine

    .github/skills/ └─ release-check/ ├─ SKILL.md ← recipe └─ scripts/ ← optional --- name: release-check description: Run the checklist and write a report. Use when asked if it’s ready to ship. --- 1. npm run release-check 2. Read release-report.md 3. Don’t fix silently
    TYPELOADEDGOOD FOR
    Instructionsalwaysteam rules
    Prompt filewhen you type /namea reusable prompt
    Skillwhen the task matchesa routine + scripts
    Custom agentwhen you pick ita role with its own tools
    MCP serverwhen a tool is neededaccess to a system
    The table is the cheat sheet of the whole talk. Skills are an open standard: the same folder works in VS Code, Copilot CLI and the cloud agent. The description is the trigger, so write it as "use when...".

    how a skill loads · think of a cookbook

    Copilot reads the index, then opens one recipe

    Analogy: a cookbook. 1: Copilot only knows the index, one line per skill. 2: when your request matches a line, it opens that recipe page. The other skills stay closed. 3: it follows the recipe and uses the tools in it, like the release-check script. 4: that is why you can have many skills without filling the context.

    bonus · beyond the editor

    Automation and remote control

    Agents that run on a schedule, and a session you can steer from your phone.

    automation

    From “I ask” to “it runs”

    Three levels, from close to far. 1: Automations in the Agents window (preview, setting chat.automations.enabled): reusable prompts, manual or on a schedule. 2: Agentic workflows in GitHub Actions: describe the job in markdown, frontmatter sets triggers and permissions. 3: Cloud agent: assign an issue or type /delegate, it works on GitHub's machines and returns a PR. Same instructions, skills and MCP config everywhere.

    remote control

    Start on the laptop, steer from your phone

    Remote control for Copilot CLI sessions is generally available. Watch progress, approve or deny tool calls, answer questions and send the next instruction from your phone or github.com. Business/Enterprise: an admin must enable the policy first.

    Keep a human on the merge button
